# Plan: Mobile drag-and-drop task reordering (#43)

**Issue:** https://github.com/Wibholm-solutions/taskflow/issues/43
**Branch:** `fix/mobile-dnd-43`
**Prior art:** PR #46 (closed — flaky CI, not code issue). Reuse same approach with refinements.

## Context

- Users want long-press-to-drag reordering on mobile within the same priority/deadline bucket
- Desktop drag-and-drop already works via HTML5 drag events (`draggable` on handle, `onDragOver`/`onDrop` on wrapper)
- Existing touch gestures: swipe-to-complete/delete (`useSwipe`), pull-to-refresh (`usePullToRefresh`)
- Reorder API: `POST /tasks/reorder` with `{ taskIds: string[] }` — already validated server-side
- Bucket logic: `getBucketKey(task)` in `TaskList.tsx` groups by deadline-urgency + priority

## Approach

Build a `useTouchDrag` hook managing the full touch-drag lifecycle:
1. **Long-press activation** (300ms on drag handle) — distinguishes from tap and swipe
2. **Visual feedback** — lifted card (scale + opacity) + blue insertion indicator
3. **Touch tracking** — document-level `touchmove` with `{ passive: false }` to prevent scroll
4. **Drop reorder** — compute new order within bucket, call `onReorder`

Key conflict avoidance:
- Long-press only activates on the `::` drag handle button (not the card body)
- `touchmove` on the handle cancels the long-press timer (finger must stay still)
- Once drag activates, document-level listeners with `preventDefault` block scroll/swipe
- `useSwipe` uses `passive: true` on the card body — no conflict since drag handle is separate

## Tasks

### Task 1: Create `useTouchDrag` hook (TDD)

**File:** `client/src/hooks/useTouchDrag.ts`
**Test file:** `client/tests/useTouchDrag.test.ts`

**Test cases (write first):**
1. Returns `null` drag state initially
2. `handleTouchDragStart(task, touch)` sets `dragState` with `draggedId` and `overIndex`
3. `touchmove` during drag updates `overIndex` based on `clientY` hitting task elements
4. `touchmove` calls `preventDefault` to block scrolling
5. `touchend` calls `onReorder` with recomputed bucket order when position changed
6. `touchend` does NOT call `onReorder` when dropped at original position
7. `touchcancel` resets state without calling `onReorder`
8. Cross-bucket drag (different `getBucketKey`) does not reorder
9. Ignores `handleTouchDragStart` for tasks not in items list

**Implementation:**
```typescript
interface UseTouchDragOptions {
  items: Task[];
  getBucketKey: (task: Task) => string;
  onReorder: (taskIds: string[]) => void;
}

interface DragState {
  draggedId: string;
  overIndex: number;
}

interface UseTouchDragResult {
  dragState: DragState | null;
  handleTouchDragStart: (task: Task, touch: React.Touch) => void;
}
```

- Use `useRef` for mutable state (items, callbacks) to avoid re-registering listeners
- `findOverIndex`: query `[data-testid="task-{id}"]` elements' `getBoundingClientRect`
- Document listeners registered once via `useEffect([], [])`
- On `touchend`: filter bucket items, remove dragged, splice at target index, call `onReorder`

## Notes

- PR #46 failed due to flaky CI (`port 3000 already in use`), not code issues. The implementation was reviewed and found sound.
- No new dependencies needed — pure React hooks + DOM APIs.
- The `useSwipe` hook uses `passive: true` listeners on the task card body. The touch drag uses `passive: false` on `document` and only activates via the drag handle. These do not conflict.
