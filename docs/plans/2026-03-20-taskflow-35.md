# Extract CompletionOrchestrator from TaskService.complete() — Implementation Plan

> **For agentic workers:** REQUIRED: Use superpowers-extended-cc:subagent-driven-development (if subagents available) or superpowers-extended-cc:executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Extract the transaction-internal write logic from `TaskService.complete()` into a standalone `executeCompletion()` function, and replace the confirmation boolean return with a thrown `SubtasksConfirmationRequiredError`.

**Architecture:** The 100-line `complete()` method is split into two layers: `complete()` owns pre-checks, transaction lifecycle, and post-reads; `executeCompletion()` owns all write logic inside the transaction (marking completion, recurrence spawning, subtask cloning). The subtask confirmation path becomes a thrown typed error instead of a nullable return shape.

**Tech Stack:** TypeScript, Drizzle ORM, Hono, Vitest

### Task 1: Create SubtasksConfirmationRequiredError and executeCompletion()

**Files:**
- Create: `server/src/services/completionOrchestrator.ts`

- [ ] **Step 1: Create the error class and function**

Create `server/src/services/completionOrchestrator.ts` with:

1. `SubtasksConfirmationRequiredError` — typed error with `code = 'subtasks_confirmation_required'`
2. Local helpers copied from taskService.ts (all five are needed for compilation):
   - `normalizeDate()`
   - `normalizeSubtaskTitle()`
   - `buildSubtaskInsert()`
   - `buildSubtaskInserts()`
   - `buildRecurringSubtaskInserts()`
3. `executeCompletion(task, options, ctx)` — **synchronous** function (must match Drizzle's synchronous transaction callback). The full transaction-internal write logic:
   - Subtask confirmation gate (throws if open subtasks and not confirmed)
   - Mark open subtasks completed
   - Mark task completed
   - Derive `completedDate` from `ctx.now.split('T')[0]` internally
   - Recurrence spawning: reuse existing instance or create new one
   - Subtask cloning to next instance
   - Returns `{ nextInstanceId: string | null }`

**Important:** `executeCompletion()` must be synchronous (not `async`) because `this.db.transaction()` takes a synchronous callback. An async function would silently discard the Promise and the transaction would commit before the function body runs.

Key imports: `eq`, `and` from drizzle-orm, `nanoid`, schema tables, `calculateNextOccurrence`, types.

**Note on helpers:** Only `buildRecurringSubtaskInserts` can be removed from `taskService.ts` after extraction. The other helpers (`normalizeDate`, `normalizeSubtaskTitle`, `buildSubtaskInsert`, `buildSubtaskInserts`) are still used by `create()` and `update()` — they stay in both files.
