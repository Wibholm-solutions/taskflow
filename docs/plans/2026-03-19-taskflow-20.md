# Plan: Add API tests for recurrence rule validation failures

**Issue:** #20
**Date:** 2026-03-19

## Context

`validateRecurrenceRule` in `server/src/routes/tasks.ts` has four distinct error paths:
1. Non-object rule → `"invalid recurrence rule"`
2. Unknown type → `"invalid recurrence type"`
3. Weekdays with empty/missing days → `"weekdays requires days array"`
4. `days_after`/`months_after` with interval < 1 → `"X requires positive interval"`

The existing API test suite (`server/tests/api.test.ts`) covers paths 2-3 on PUT only, and path 4 partially (only `days_after` with missing interval, not with `interval: 0`). No recurrence validation is tested on POST. Path 1 (non-object rule) is entirely untested.

## Approach

Add a new `describe` block inside `POST /todo/api/tasks` and extend the existing `PUT /todo/api/tasks/:id` block with the missing cases. Each test sends a minimal payload with a specific malformed `recurrenceRule` and asserts 400 + the exact error message.

## File to modify

- `server/tests/api.test.ts`

## Tasks

### Task 1: Add POST recurrence validation tests

Add inside `describe('POST /todo/api/tasks')` — 5 new tests:

```
it('should reject non-object recurrenceRule on create')
  → { title: 'T', recurrenceRule: 'daily' }
  → 400, { error: 'invalid recurrence rule' }

it('should reject unsupported recurrence type on create')
  → { title: 'T', recurrenceRule: { type: 'monthly' } }
  → 400, { error: 'invalid recurrence type' }

it('should reject weekdays without days on create')
  → { title: 'T', recurrenceRule: { type: 'weekdays', days: [] } }
  → 400, { error: 'weekdays requires days array' }

it('should reject days_after with interval below 1 on create')
  → { title: 'T', recurrenceRule: { type: 'days_after', interval: 0 } }
  → 400, { error: 'days_after requires positive interval' }

it('should reject months_after with interval below 1 on create')
  → { title: 'T', recurrenceRule: { type: 'months_after', interval: 0 } }
  → 400, { error: 'months_after requires positive interval' }
```

### Task 2: Add missing PUT recurrence validation tests

Add inside `describe('PUT /todo/api/tasks/:id')` — 3 new tests (paths not yet covered):

```
it('should reject non-object recurrenceRule on update')
  → { recurrenceRule: 42 }
  → 400, { error: 'invalid recurrence rule' }

it('should reject months_after with missing interval on update')
  → { recurrenceRule: { type: 'months_after' } }
  → 400, { error: 'months_after requires positive interval' }

it('should reject days_after with interval of 0 on update')
  → { recurrenceRule: { type: 'days_after', interval: 0 } }
  → 400, { error: 'days_after requires positive interval' }
```

Note: The existing update tests already cover unknown type (line 537), empty weekdays (line 573), and missing days_after interval (line 555). We only add the gaps.
