# Remove Playwright from Production Docker Image — Implementation Plan

> **For agentic workers:** REQUIRED: Use superpowers-extended-cc:subagent-driven-development (if subagents available) or superpowers-extended-cc:executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Reduce the production Docker image from ~4.65 GB to ~300 MB by removing Playwright and test files.

**Architecture:** Multi-stage Dockerfile — build stage compiles the app, production stage copies only runtime artifacts (`dist/`, prod `node_modules`, `package.json`). Tests run in CI (already handled by `.github/workflows/ci-cd.yml`), not inside the production container.

**Tech Stack:** Docker multi-stage builds, node:20-slim

---

## Context

### Current Dockerfile (`Dockerfile`)

The existing Dockerfile already uses two stages but the production stage still:
1. Runs `npx playwright install-deps chromium` (~289 MB system packages)
2. Copies Playwright browser binaries from builder (~652 MB)
3. Copies all test files (`server/tests/`, `client/tests/`, `e2e/`)
4. Runs `chown -R` on everything including Playwright (~1 GB layer)

### CI Pipeline (`.github/workflows/ci-cd.yml`)

Tests already run in CI **before** deploy:
- `unit_coverage` → runs `npm run test:coverage`
- `build` → runs `npm run build`
- `e2e` → installs Playwright, builds, runs `npm run test:e2e`
- `deploy` → builds Docker image and deploys (only on push to master)

Tests do NOT need to run inside the production container.

### Production Healthcheck

`~/apps/taskflow/docker-compose.yml` uses `wget` for healthcheck. `node:20-slim` does NOT include `wget`. The healthcheck must be updated to use `node` (always available) or we install `wget` in the slim image.

### Task 1: Rewrite Dockerfile as lean multi-stage build

**Files:**
- Modify: `Dockerfile`

- [ ] **Step 1: Replace the Dockerfile with a lean multi-stage build**

```dockerfile
FROM node:20 AS builder
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build

FROM node:20-slim AS production
WORKDIR /app
COPY --from=builder /app/dist ./dist
COPY --from=builder /app/package.json .
COPY --from=builder /app/package-lock.json .
RUN npm ci --omit=dev && npm cache clean --force
EXPOSE 3000
USER node
CMD ["node", "dist/server/index.js"]
```

Key changes from current Dockerfile:
- Production stage uses `node:20-slim` (not `node:20`)
- No `playwright install-deps` in production
- No Playwright browser binaries copied
- No test files copied (`server/tests/`, `client/tests/`, `e2e/`)
- No `chown -R` needed (no Playwright dirs, USER node applied after COPY)
- Fresh `npm ci --omit=dev` instead of copying full `node_modules` (ensures no devDependencies)

- [ ] **Step 2: Build the image locally and verify size**

### Task 2: Update production healthcheck

**Files:**
- Modify: `~/apps/taskflow/docker-compose.yml`

The production compose uses `wget` for healthcheck, but `node:20-slim` doesn't include `wget`. Switch to a `node`-based healthcheck.

- [ ] **Step 1: Update healthcheck in production compose**

Change from:
```yaml
healthcheck:
  test: ["CMD", "wget", "-q", "--spider", "http://localhost:3000/todo/api/health"]
```

To:
```yaml
healthcheck:
  test: ["CMD", "node", "-e", "fetch('http://localhost:3000/todo/api/health').then(r=>{process.exit(r.ok?0:1)}).catch(()=>process.exit(1))"]
```

This uses Node.js's built-in `fetch` (available in Node 20+) — no extra binaries needed.

- [ ] **Step 2: Verify healthcheck syntax is valid**

Run:
```bash
docker compose -f ~/apps/taskflow/docker-compose.yml config --quiet && echo "Valid"
```
Expected: "Valid" (no errors)

- [ ] **Step 3: Commit**

```bash
cd ~ && git add apps/taskflow/docker-compose.yml
git commit -m "fix: update taskflow healthcheck to use node instead of wget

node:20-slim doesn't include wget. Uses Node.js built-in fetch instead."
```
