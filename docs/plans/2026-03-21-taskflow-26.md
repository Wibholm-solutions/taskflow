# Plan: Fix reorder test — upcoming task leaks into active bucket

**Issue:** [#26](https://github.com/Wibholm-solutions/taskflow/issues/26)
**Date:** 2026-03-21

## Context

The reorder validation test (`api.test.ts:287`) creates an "Upcoming" task with `notBefore: '2026-03-17'`. That date is now in the past, so `listTasks()` classifies the task as active instead of upcoming, causing the assertion on line 341 to fail (`['High', 'First', 'Second', 'Upcoming']` instead of `['High', 'First', 'Second']`).

The test is currently wrapped in `it.fails()` as a canary. The fix follows the established pattern in `taskService.test.ts` which uses `vi.useFakeTimers()` + `vi.setSystemTime('2026-03-16T10:00:00.000Z')` to freeze time before the `notBefore` date.

## Approach

Pin the system clock to `2026-03-16` inside the reorder validation test using Vitest fake timers, matching the existing convention used in 7+ tests in `taskService.test.ts`.

## Tasks

### Task 1: Add fake timers and remove `it.fails()` wrapper

**File:** `server/tests/api.test.ts`

1. Add `vi` to the vitest import on line 1:
   ```ts
   import { describe, it, expect, beforeEach, afterEach, vi } from 'vitest';
   ```

2. Change `it.fails(` back to `it(` on line 287

3. Add fake timers at the start of the test callback (after the opening `async () => {`):
   ```ts
   vi.useFakeTimers();
   vi.setSystemTime(new Date('2026-03-16T10:00:00.000Z'));
   ```

4. Add cleanup at the end of the test (before the closing `}`):
   ```ts
   vi.useRealTimers();
   ```
