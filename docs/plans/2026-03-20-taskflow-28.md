# Fix: Upcoming Task Leaks into Active List After Rejected Reorder

> **For agentic workers:** REQUIRED: Use superpowers-extended-cc:subagent-driven-development (if subagents available) or superpowers-extended-cc:executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix the reorder test so "upcoming" tasks with a future `notBefore` date are correctly excluded from the active list.

**Architecture:** The bug is a stale test date, not a service-layer defect. The test hardcodes `notBefore: '2026-03-17'` which is now in the past, so `listTasks()` classifies it as active. Fix by pinning the system clock with `vi.useFakeTimers()` (matching existing patterns in `taskService.test.ts`) and removing the `it.fails()` canary wrapper.

**Tech Stack:** Vitest (fake timers), Hono, better-sqlite3

---

## Root Cause Analysis

**File:** `server/tests/api.test.ts:301`
**Problem:** `notBefore: '2026-03-17'` was a future date when written but is now in the past (today = 2026-03-20).

**Flow:**
1. Test creates task with `notBefore: '2026-03-17'`
2. `listTasks()` at `server/src/services/taskService.ts:269` computes `today = new Date().toISOString().split('T')[0]` = `'2026-03-20'`
3. Filter at line 274: `'2026-03-17' > '2026-03-20'` is `false` -> task classified as **active**
4. The reorder validation at `taskService.ts:429-454` is correct — it properly rejects invalid payloads via `throw new Error('invalid reorder payload')` with no DB side effects
5. The assertion at line 341 fails because the "Upcoming" task now appears in the active list

**Conclusion:** The service layer is correct. Only the test needs fixing.
