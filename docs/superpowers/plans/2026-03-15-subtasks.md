# Subtasks Implementation Plan

> **For agentic workers:** REQUIRED: Use superpowers:subagent-driven-development (if subagents available) or superpowers:executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add one-level subtasks with a dedicated backend model, inline editing in the task modal, parent completion confirmation, and overview progress indicators.

**Architecture:** Keep top-level tasks in `tasks` and add a dedicated `subtasks` table for one-to-many child rows. Extend the backend to operate on task aggregates, then update the client to edit and display parent tasks with inline subtask state while keeping subtasks out of the top-level list.

**Tech Stack:** TypeScript, React 18, Vite, Hono, Drizzle ORM, SQLite, Vitest, Playwright

---

## Notes for the Implementer

- Follow TDD strictly: do not write implementation before the corresponding failing test exists.
- Keep subtask logic server-authoritative; the client should react to `subtasks_confirmation_required`, not reinvent the invariant.
- Preserve current recurrence behavior for parent tasks unless a test proves a required adjustment.
- Do not expand scope into nested subtasks, ordering UIs, or independent subtask deadlines.
- If you are not in a dedicated worktree, create one before implementation if your harness supports it.
